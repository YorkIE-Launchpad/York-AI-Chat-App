Product & UX redesign · proposal for review

From a toolbox of AI features to one calm place that runs your workday.

GrowthOS can already do a lot: brief you, prep meetings, track promises, run automations and act across Slack, Gmail, Jira and Hub. The problem is that it shows all of this as separate products. This proposal reorganizes the app around the one question York staff open it to answer, and refreshes the look while keeping the York IE navy and teal.

01Who it's for and the job they hire it for

The main user is a York IE team member (delivery, GTM, leadership) moving between client calls, Slack, email, Jira and Hub all day.

“When I sit down, or come out of a meeting, show me what needs me right now and help me deal with it in a couple of clicks, without me having to check six tools.”
JOB 1 · KNOW

What needs me?

One prioritized list across every source, with the reason it matters.

JOB 2 · ACT

Help me handle it

Draft, prep, investigate or fill in, starting from that item with its context already attached.

JOB 3 · KEEP

Don't let things slip

Promises are tracked and routine work is automated.

02What gets in the way today

From reading the current renderer code (about 37k lines in src/renderer).

Four places answer “what needs me?”

The Home briefing, Matter (signals, radar, focus lenses, focus score), Next-up meeting and Loops each show part of the picture. Users have to put it together themselves.

Seven ways to start a conversation

New chat, incognito, the Home composer, the Ask Growth OS popup, Screen Snap, Matter's ask bar and Live Assist. Each has a different UI and a different idea of where the answer ends up.

Billing shows up as navigation

The General / Folders / Hub / Project workspace switch decides who pays for models, and it appears as gate banners and “needs your key” errors. Most staff just want company models to work.

Automations are split in two

Workflows has its own page, while Scheduled tasks are inside Settings. They are the same idea: GrowthOS doing something without being asked.

Pages aren't routes

Pages are switched by separate flags (showMatter, showLoops and so on). There's no back/forward or deep linking, and every new page adds more conditions to App.tsx.

Internal names in the UI

“Matter”, “Loops”, “orbits”, “lenses”, “focus score” are meaningful to the team that built them, but a new hire has to learn them before the product makes sense.

03Design principles

1

Answer first

Every screen opens with a sentence that summarizes the state, then the list. Show the answer, not a dashboard.

2

One composer, one history

Every entry point (⌘K, Snap, Live Assist, an item on Today) creates a normal chat in the same history.

3

Act from where you are

Each item has one primary action. Context goes with you into the chat, so you never re-explain.

4

Show detail on demand

Tool calls, reasoning, scores and raw JSON are one click away, never in the main view.

5

The user approves outside actions

Sending, posting or changing anything outside the app is always an explicit, labelled button.

6

Plain language

Use the words a new hire would use. Internal names stay in code, not in the UI.

05Decisions that need your call

The prototype assumes the recommended option for each of these.

Rename Matter to Today and Loops to Follow-ups

Plain names help adoption. “Matter” can stay as the name of the engine in docs and code. The cost is retraining current users, which can be softened with a one-time “Matter is now Today” notice.

Needs your call

Default every York user to the Hub workspace

Company models just work. General/Folders (bring your own key) moves into the workspace menu as “Personal (your OpenRouter key)”. The key prompt only appears if someone picks it.

Needs your call

Retire the separate Ask Growth OS popup

⌘K covers it inside the app, and ⌥Space opens the same command bar system-wide. Answers go into the normal chat history.

Recommended

Make the Matter radar the main visual on Today

The radar is the one view that shows at a glance how much is close to you and where it's coming from. Keep the rings (Now at the core, then Today, This week, Watching) and make them the same groups as the list, so the radar and the list are two views of the same items, linked on hover and click. Two fixes: the angle becomes one slice per source instead of a random hash of the item ID, and the sweep only animates while a scan is actually running.

Recommended

Move the focus score behind “How this was ranked”

A score out of 100 doesn't tell anyone what to do next. It stays available for power users and for tuning the ranking.

Recommended

Private chat instead of a permanent incognito button

Same feature, available from the New chat menu and ⇧⌘N, instead of taking up a permanent spot in the sidebar.

07Rollout plan

Each phase ships on its own behind a redesign feature flag, with a toggle for internal users first. Main-process changes are limited to tool error details (phase 1) and a shared automations list (phase 4).

PHASE 0 · ~1 wk

Foundations

Groundwork that makes the rest cheap and safe.

  • Replace the show* flags with a small router (hash routes: /today, /chat/:id, /follow-ups…) and get back/forward and deep links for free.
  • Update the theme variables, and add Button, Tabs, ListItem and Card components to replace one-off class strings.
PHASE 1 · ~2 wk

New shell + ⌘K + tools status

New sidebar (4 items + chats), the command bar replacing chat search and the Ask popup, and the workspace menu defaulting to Hub.

  • Tools status pill in the title bar, built on the existing mcp.getServerStatus() polling (status + toolCount per server). It replaces ToolsConnectingStatus, which today only shows on the home screen at startup.
  • Retry uses the existing mcp.reconnectServer(id). One small main-process addition: return lastError and lastCheckedAt on McpServerStatus so a failed tool can say why. Today it only reports failed.
PHASE 2 · ~2 wk

Today

Merge the Welcome screen, Matter briefing, next-up meeting and due Loops into one ranked list on top of the existing Matter and Loops data, grouped by the existing MatterOrbit values. Reuse MatterRadar as the main visual, with source slices instead of hashAngle and shared hover/selection state with the list. Starting a chat from an item carries its context into the chat (this already exists as Matter's chat prefill).

PHASE 3 · ~2 wk

Chat + Inspector

Collapse tool steps into a single summary line, add numbered source citations, and combine the Context panel and HTML preview into one tabbed Inspector. Split ChatView.tsx (2.6k lines) along the way.

PHASE 4 · ~2 wk

Follow-ups, Automations, Settings

Rename and polish Loops, merge Workflows and Schedules into one list (needs a shared list API from the main process), and regroup Settings. Then remove the flag.
